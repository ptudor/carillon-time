Carillon 1.2.0 refreshes the metrics dependency and the tools used to build and
verify releases. The NTP, leap-table, and clock-discipline implementation is
unchanged from 1.1.0.

### Dependencies and release tooling

- Update `github.com/prometheus/common` from v0.71.0 to v0.72.0 and refresh the
  notices shipped with every archive and package.
- Update GoReleaser to v2.18.2, the Go vulnerability scanner to v1.8.0, and the
  SHA-pinned artifact-upload Action to v7.0.2.
- Keep Go 1.27.1 as the release toolchain. Source builds require Go 1.26 or later.
- Keep dependency alerts and scheduled vulnerability checks enabled while
  handling dependency updates through repository maintenance instead of
  automatically opened pull requests.

### Upgrading

No configuration migration is required when upgrading from 1.1.0. Back up
configuration, shared keys, and persistent state before installing, and preserve
the `leap/` cache beside the drift file. Packages preserve existing configuration
and do not enable, start, or restart the daemon. Restart the service explicitly
when ready to use the new executable.

For an upgrade from 1.0.0, read the
[1.1.0 upgrade guidance](https://github.com/ptudor/carillon-time/blob/v1.2.0/docs/release-notes/v1.1.0.md#upgrading-from-100):
refclock and serving hosts require a current leap table and an acquisition mode.

### Downloads and verification

| Platform | Architectures | Files |
| --- | --- | --- |
| Linux | amd64, arm64 | `.tar.gz`, signed `.rpm`, signed `.deb` |
| FreeBSD | amd64, arm64 | `.tar.gz` with deployment examples |

Each archive and Linux package contains `carillon` and `carillonctl`. Verify
`checksums.txt.sig`, the SHA-256 hashes, and the GitHub build attestation before
installation. The release signing key remains
`8C4F 58EF B945 4902 267D 9B3E 426C 4AA2 1A40 0728`.

Release checks cover native race tests on Linux amd64, Linux arm64, and macOS
arm64, Linux ABI checks, cross-builds, signed package lifecycle tests in Debian
and Fedora, vulnerability scans, and secret scans. These checks do not adjust the
host clock or access reference-clock hardware. FreeBSD binaries are
cross-compiled; live GPS/PPS leap acceptance remains pending. See the
[known limitations](https://github.com/ptudor/carillon-time/blob/v1.2.0/docs/limitations.md).
