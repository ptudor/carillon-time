Carillon 1.1 adds durable leap-second data with authenticated distribution between
Carillon hosts, lets a Linux GPS share one serial port between its sentences and
its pulse, and signs the Linux packages.

### Durable leap-second data

- A GPS/PPS host needs advance leap information even when its network sources
  disappear. `[leap] acquire` now selects where it comes from: `manual` (the
  existing `daemon.leapfile`), a seed that downloads `leap-seconds.list` from
  IERS or NIST over HTTPS, or `peers`, which learns the original file from an
  upstream Carillon over an authenticated NTP extension.
- Distribution is explicit at every hop. A learner accepts a table only from a
  `[[server]]` marked `leap_trust = true` with an AES-128-CMAC key, and a server
  answers only keys listed in `serve.leap_keys`. A time-service key is not
  permission to request leap data. The wire protocol is experimental.
- Tables are kept as original bytes in a private atomic cache beside the drift
  file. Digest, replay, history, and rollback checks guard acceptance, and an
  update activates without restarting the discipline loop.
- The seed is a polite client of a shared public server: it identifies itself,
  makes conditional requests so an unchanged file costs a `304`, obeys
  `Retry-After`, never asks more often than every 15 minutes even across
  restarts, and ignores proxy environment variables. IERS and NIST date the file
  differently, so a seed uses one publisher with no fallback between them.
- `carillonctl tracking` reports the leap source, readiness and its reason, the
  table's digest, provider and expiry, and acquisition state.

See [leap-table distribution](https://github.com/ptudor/carillon-time/blob/v1.1.0/docs/leap-distribution.md)
for trust, configuration, and recovery.

### One serial port for a Linux GPS

`pps = "dcd"` now works on Linux as it does on FreeBSD. Carillon attaches the N_PPS
line discipline to the receiver's tty itself, and the sentence stream keeps
arriving on the same port, so a combined receiver no longer needs an `ldattach`
service or a second device. The manual systemd unit grants the tty `rw`, which
attaching the discipline requires. `pps = "cts"` remains FreeBSD-only, because
the Linux discipline captures carrier detect alone.

### Fixes

- The systemd units now allow `AF_NETLINK`. Without it the daemon kept time but
  silently skipped two startup guards: refusing a source that is itself or is
  synchronized to it, and recognizing directed broadcasts. The only symptom was
  a warning at startup.
- Replies from a FreeBSD listener bound to a specific IPv4 address no longer
  fail with `EINVAL`.
- `golang.org/x/sys` is updated to v0.48.0.

### Signed packages and manifest

- RPMs, DEBs, and `checksums.txt` are signed with the project's OpenPGP release
  key, fingerprint `8C4F 58EF B945 4902 267D  9B3E 426C 4AA2 1A40 0728`. The
  public key is
  [`packaging/release-signing-key.asc`](https://github.com/ptudor/carillon-time/blob/v1.1.0/packaging/release-signing-key.asc)
  in the repository. The same key signs Sigillum releases.
- After `sudo rpm --import release-signing-key.asc`, `rpm -K` reports
  `digests signatures OK` and DNF installs the package with
  `--setopt=localpkg_gpgcheck=1`; the earlier `localpkg_gpgcheck=0` is no longer needed.
- APT and dpkg do not check a local DEB's embedded signature. For DEBs and
  archives, verify `checksums.txt.sig` with `gpg --verify`, then the hashes.
- The release workflow refuses to build unless its signing secret matches the
  published key, and verifies every signature against that key before
  attestation and publication. Release 1.0.0 remains unsigned.

### Upgrading from 1.0.0

Back up configuration, shared keys, and persistent state first. **A refclock or
serving host now requires a current leap table before it reports
synchronization, and its configuration fails validation without a manual leap
file or an acquisition mode.** Choose the seed or learner role before restarting,
and run `carillon -check` against the intended configuration. An empty automatic
cache passes the check; service then waits for UTC and a durably accepted table.
Preserve the `leap/` cache beside the drift file across upgrades and restarts.
A network-only client needs no new settings.

When several hosts are upgraded, restart the upstream first. Packages preserve
existing configuration and do not enable, start, or restart Carillon; the old
process continues until you restart it. The packaged unit changed; the package
reloads systemd, and the new unit takes effect at that restart.

### Verification and scope

CI runs native race tests on Linux amd64, Linux arm64, and macOS arm64, safe ABI
checks where supported, every release cross-build, Debian 13/Fedora 43 package
lifecycle tests with signature checking enforced, vulnerability scans, and
full-history secret scans. These tests do not adjust the host clock or access
reference-clock hardware.

Leap handling is covered by fake-clock simulations of positive and negative
leaps, poisoning, replay, storage faults, and restart or expiry, and the
distribution chain runs on the maintainer's hosts. Live GPS/PPS acceptance of a
leap event is still pending. The shared-tty change rests on kernel source, a
pseudo-terminal test on a running Linux kernel, and `ldattach` practice; no
receiver has yet shared one port between its sentences and a live pulse on a
Carillon host. Read the
[known limitations](https://github.com/ptudor/carillon-time/blob/v1.1.0/docs/limitations.md)
before choosing a deployment.

FreeBSD release binaries are cross-compiled. Hardware accuracy depends on the
receiver, PPS path, kernel, and deployment; this release does not make a measured
accuracy guarantee. NTS, PTP, and hardware NIC timestamping are outside its scope.
