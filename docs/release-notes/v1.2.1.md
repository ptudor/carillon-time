Carillon 1.2.1 limits how far a single observation can move the base clock
frequency after switching sources or shortening the poll interval. In a
regression replay with a 27-minute gap, a 16-second poll, and a 1 ms offset,
the first frequency correction fell from 98.88 ppm to 0.98 ppm. The full
phase correction begins on the next clock tick. Later independent updates
resume the normal frequency gain.

### Acquisition and tracking

- An unreachable association sends one probe per scheduled poll. A usable
  reply starts the remaining three requests of an `iburst`. RATE backoff
  applies throughout reacquisition.
- `carillonctl tracking` and HTTP status identify the currently selected
  source and the source of the last accepted clock update. The update age
  uses monotonic time. The decision shows when the spike gate rejected an
  offset or the filter is still using an earlier sample.
- Public servers report a socket buffer shortfall after reading the bound
  socket. Logs include the requested and granted sizes and the relevant sysctl.

### Installation

Existing 1.2.0 deployments can install the binaries and restart with their
current configuration, drift file, and leap cache. For a first installation
using IERS or NIST, run `carillon prepare-leap -config /path/to/carillon.toml`
as the service account while the incumbent daemon is synchronized. This
fetches and validates the initial leap table before cutover. Carillon still
qualifies its clock sources at startup.

Verify the signed checksums and build attestations for downloaded archives
and packages. [Verification instructions](https://github.com/ptudor/carillon-time/blob/v1.2.1/docs/releases.md#verify-a-download)
